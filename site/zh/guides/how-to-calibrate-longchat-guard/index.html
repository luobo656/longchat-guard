LongChat Guard 如何校准与自动读取 ChatGPT 长会话？

LongChat Guard 不读取 OpenAI 官方剩余额度。它以本地可验证的对话测量和用户亲自确认达到过长度上限的历史会话作为经验参考，因此只有证据完整时才显示确定性的风险状态。

简短答案： 安装并同意本地处理，打开真正达到会话长度上限的历史对话，选择校准，让自动读取完成上下滚动和完整性检查，再返回正在使用的会话查看风险。普通长会话不能冒充触顶样本。

校准前：先找到真正触顶的历史会话

必须是你亲自观察过 ChatGPT 提示会话长度达到上限的历史对话。会话消息很多、网页加载慢、文件上传失败或暂时受到频率限制，都不能单独证明它已经达到会话长度上限。如果没有可靠触顶样本，插件会保持未校准，不会编造一个额度。

三步完成首次设置

1. 安装并明确同意

安装 LongChat Guard，打开 chatgpt.com，阅读并同意本地处理提示。无需创建插件账号，也不需要 OpenAI API Key。

2. 打开已确认触顶的历史对话

在对应会话中使用校准操作：遇到真实长度错误候选时选择「用此会话校准」，或通过菜单的「重新校准提醒基准」发起读取。

3. 完成一键自动读取

保持 ChatGPT 标签页位于前台。浏览器模拟滚轮自动加载较早消息、返回最新消息，随后原版读取器检查消息连续性与完整性；可以随时取消，不会保存不完整结果。

只有校准参考适用于当前测量环境，并且当前会话本身已可靠测量，插件才会显示经验风险状态。历史读取成功不等于知道 OpenAI 官方上限。

「完整读取当前会话」和「校准」不是一回事

完整读取当前会话用于恢复或检查当前会话的测量负载 L；使用已确认触顶的历史会话校准用于建立经验失败参考 R。读取普通进行中的会话，不会自动把它当成新的上限。两项操作共用同一套自动滚动准备和正文计量规则。

关键原则：没有真正触顶的证据，就不能建立看似精确却实际错误的风险基准。

界面状态代表什么？

未校准

当前环境还没有可使用的真实历史失败参考。正常继续使用即可，不要为了让进度条出现而拿普通长聊天校准。

暂无法判断

当前会话的消息完整性、顺序或读取环境无法证明可靠。在适用的长会话中可以主动完整读取，再根据检查结果判断。

风险较低／偏长／接近风险／高风险

这是相对本地历史失败参考和实际增长趋势的经验分档，不是官方 Token 剩余额度，也不是精确百分比。

为什么自动读取需要浏览器调试权限？

用户主动发起完整读取或校准时，插件临时使用浏览器的 debugger 强权限，向当前前台 ChatGPT 标签页发送模拟鼠标滚轮操作。完成、取消或失败后会解除调试连接；正常实时监测不会启用调试器。该浏览器权限本身较广，因此出现较明显的系统警告是可能的。

聊天文本由网页内容脚本在浏览器内瞬时处理用于本地估算，不通过调试器导出，不上传开发者分析服务器。详情见隐私政策。

什么时候应该开新会话？

当本地经验风险提示值得整理时，可以在当前 ChatGPT 会话中使用插件提供的续接提示词，让当前模型整理目标、已经确认的决定、重要限制、文件或代码状态、未解决问题和下一步，再自行将生成的内容带到新会话。插件不会代替你自动搬运对话。

风险提醒和续接结果都不代表官方上下文上限。

常见问题排查

还要用鼠标手动滚动吗？

不需要。4.3.0 使用一键自动读取。读取时保持标签页在前台，避免操作网页，需要时可以取消。

没有达到上限的旧会话，能提前校准吗？

不能用它建立可靠的失败参考。只有真实长度上限事件得到用户确认、历史可以完整读取时才能校准。

能显示官方 Token 剩余额度吗？

不能。内部内容单位不等于 OpenAI 官方 Token 数，也不存在适用于所有会话的固定官方上限估值。
