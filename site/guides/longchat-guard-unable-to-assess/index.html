Troubleshooting · Version 4.3.0

Why does LongChat Guard say “Unable to assess”?

Quick answer: “Unable to assess” means that the extension cannot prove this chat was read reliably. It does not mean you have room left or that you reached the limit. A fresh install may instead show “Not calibrated” because a confirmed historical limit reference is absent.

2026-10-22

Start with the correct status

Not calibrated

There is no usable, user-confirmed historical conversation-length failure reference (R). Reading an ordinary long chat cannot safely create one.

Unable to assess

The current chat's measured history, sequence, or environment cannot yet be proven complete. This is different from knowing its remaining capacity.

Automatic reading stopped

The user cancelled, the foreground tab changed, or the browser could not finish the scroll and verification. Incomplete results are rejected rather than saved.

If ChatGPT has already reached a hard conversation limit

A hard limit can prevent new messages in that same thread, so “ask the old conversation for one last summary” may no longer work. Use any existing user-visible information and source files you can still access, gather the current objective, confirmed decisions, constraints and unfinished work, and begin a fresh thread. The extension does not bypass ChatGPT's limit or automatically transfer a conversation.

For an actionable example, read how to prepare a compact handoff. If you use ChatGPT Projects, OpenAI's Projects documentation explains that project context and memory vary with plan and settings. Do not assume a new project chat can reconstruct every old turn.

Why does automatic reading require debugger access?

Only when you start a full read or calibration, LongChat Guard temporarily uses the browser's powerful debugger permission to send mouse-wheel input to the active ChatGPT tab. The original reader then checks message continuity. Normal passive risk monitoring does not attach a debugger; the extension detaches at the end, on cancellation or error. The browser permission itself is broader than this self-imposed restriction. Read the exact disclosure.

Illustrative scenario (not user telemetry)

Example: You open a months-old research thread directly from history. Only the most recent messages have rendered, so the panel says “Unable to assess.” You request the full read, keep the tab active, and the reader checks history in both directions. If verification succeeds, current load can be updated. If it fails, the status remains conservative. A risk track still requires a separately confirmed historical failure reference.

Frequently asked questions

Does “Unable to assess” mean ChatGPT is out of tokens?

No. It describes evidence quality for the extension's local measurement, not an official token or capacity reading.

Will recalibrating solve every unknown status?

No. The historical reference and current chat coverage are separate. Do not overwrite a reliable historical reference with an unverified sample.

What if automatic reading repeatedly fails?

Preserve your local data, verify you're in the correct foreground ChatGPT tab, and retry. Report the website/browser version and sanitized steps in GitHub Issues—never paste private conversation text.
